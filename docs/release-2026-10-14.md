# CareSphere multilingual-interface release — October 14, 2026

Versions: **iPhone 3.5.0 (12)**, **Android 1.5.0 (6)**, **web 1.3.0**. These replace the earlier downloadable 3.1/1.1 builds.

## What is included

An initial offline interface localization for English, Spanish, Simplified Chinese, Filipino/Tagalog and Vietnamese: 458 messages with four translations each, persistent native/web selectors, translated activity search and matching-local-voice speech. Notes, custom phrases and care records remain untouched. **Advanced content can fall back to English; translations require fluent-speaker and safety review.** [Detailed language scope](languages.md).

All 12 requested feature areas now have implementations: Simple Mode, visual routines, communication cards, personal photo conversation/matching, comfort preferences, trusted contacts, appointment questions/follow-ups, routine undo and note recovery, encrypted backup/restore, interest prompts, optional first-use guidance, native iPhone Apple Intelligence drafting, and device-to-device sharing. See [the feature guide](personal-tools.md) for exact scope and differences.

**The backend design was removed.** Selected notes/routines transfer as passphrase-encrypted `.caretransfer` files. Send through AirDrop, Quick Share, another chosen app or saved files. The recipient previews and selects copies before importing. Existing data is not overwritten. No account, server, automatic sync, proprietary phone-to-phone Bluetooth pairing, expiring links or remote revocation is provided. [Sharing guide and protocol](device-sharing.md).

| Android | 30 JVM tests including backup and cross-platform transfer crypto; lint; APK signature; emulator checks for empty real-only vitals, persistence, search/favorites, edits, large text/dark mode, routine undo, communication cards and browser-produced encrypted file preview/import |
| Web | 37 unit tests; production build; 26 browser interaction/responsive tests; offline production reopening test; npm dependency audit |

The packaging script refuses incomplete/failed CI or mismatched executable/configuration/test sources. Each final download has a **BUILD_VERIFICATION.json** containing the successful run URLs and tested source commits, and a SHA-256 sidecar. Native README-only updates are excluded from the compiled-source comparison and are independently hashed in the archive. The mobile archive is extracted and the Xcode project checked again before delivery.

Browser checks include selective import while offline, duplicate receipts, note recovery, encrypted backup preview/restore, explicit contact handoffs, photo import, visual-routine pause, largest text, responsive layouts and undo. A transient Android success dialog is not used as proof of import: the emulator verifies the persistent preview and resulting note in Care. Test records live only in test fixtures/emulator storage and are not prefilled into production app data.

## Important limits

These are development builds, not store releases or clinical software. iPhone installation needs compatible Mac/Xcode signing. Android is debug-signed and debuggable, and its certificate may differ from an older CI build. Keep old records before uninstalling; use Android Studio's stable local debug key when continuing development on your own machine.

Nearby discovery and delivery between physical phones, real BLE, Apple Intelligence model availability/responses, intended-user accessibility and the user's Mac signing are still manual checks. The compatible crypto format and emulator import do not prove actual AirDrop/Quick Share delivery. There is no fabricated paired/delivered state.

Backups are platform-specific; interoperable transfers intentionally contain only selected notes/routines. A weak passphrase can be guessed. A recipient can keep/forward copies. Whole-data plaintext exports remain outside local encryption protections; review their scope carefully. Android's basic text export excludes personal photos, contacts and recovery history and is size-limited; encrypted backups preserve the full Android data instead.

Activities and AI drafts are optional practice/organization, not validated dementia/autism treatments, clinical assessments, diagnosis or medication advice. No invented people or generated vital signs are added.

## Direct local connection update

Both native apps can now offer/receive the same encrypted snapshots over private Wi-Fi/hotspot sockets, covering all three phone pairings without a hosted backend. The user enters a device address and eight-digit connection code, separately from the encryption passphrase. The new **Find nearby devices** flow adds opt-in Bonjour/Android DNS-SD discovery; Bluetooth radio pairing is not used. Foreground-only offers last up to five minutes and stop on navigation/background. Public/ambiguous endpoints, redirects, excessive headers/bodies and wrong codes are rejected. Tests add native live socket roundtrips, framing/bounds/address validation, cancellation, and an Android emulator LAN fetch/unlock/selective-import path. The web app retains encrypted-file delivery. Physical pairwise transfers and hotspot/router compatibility remain manual acceptance work.


## Nearby-device discovery update

The native receive flow now has **Find nearby devices**, so most private Wi-Fi users can select the sender’s generic label rather than type an address. It uses standard Bonjour/Android NSD, not a hosted directory. No code, passphrase or care records are broadcast. Discovery is bounded, foreground-only and cancellable; it does not grant trust or import anything. The manual address and encrypted-file fallbacks remain. The Android test APK exercises actual OS publication, discovery, resolution, encrypted exchange and Stop; it is not distributed as the app. The discovery-only milestone had 38 Swift and 27 JVM tests; this multilingual release extends those totals to 42 and 30, plus the emulator instrumentation and UI smoke flows.
